- **Deterministic E2E passed.** `bun test` at commit `3887703`: 573 tests across 74 files pass with zero failures (2,646 assertions), including the bounded full-system run `tests/full-system.test.ts` covering RSS ingestion, a signed Resend inbound webhook plus fake Receiving API, interest-driven analysis/scoring, budgeted outside-subscription discovery, an end-to-end frozen-edition send through a fake delivery, restart over a persistent SQLite database without duplicates, and 401 denial of unauthenticated private routes. `bun run typecheck` and `bun run smoke` pass on the same commit; CI runs `bun test` with no live providers, no real email and no external model calls.

Deterministic and fake-provider evidence does not substitute for a live pass; the stages below remain visibly tracked and must not be closed until executed by an operator.

## Notes on blocked stages

- The blockers are external, not code: a live Resend receiving/sending setup, a real search-provider credential, and an operator-maintained deployment. Repo configuration already documents the required setup keys (`.env.example`, README configuration table); no credential lives in this repository or in CI.
- Each deterministic test named above runs on `bun test` in CI and keeps to the no-live-keys rule. A live stage passes only when the operator records a dated, redacted row replacing the "Not run / blocked" status above.
- The deterministic `tests/full-system.test.ts` run can be re-executed at any time to re-confirm the "deterministic passed" half of this distinction; it never sends real email or calls external services.
