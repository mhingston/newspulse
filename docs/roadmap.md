## Current implementation and evidence

M1 is implemented in [PR #1](https://github.com/mhingston/newspulse/pull/1): native RSS/Atom, OPML, canonical items and provenance, SQLite/Drizzle/FTS5, durable polling jobs, four authenticated read-only MCP tools, CLI, Docker Compose, backup/restore and tests. A follow-up readiness review added CI and fixed shutdown so it stops claiming new work after the active poll. See the PR for current checks and merge status; this document does not claim a PR is merged merely because code exists on a branch.

Observed evidence: `src/domain.ts`, `src/adapters/`, `src/db/`, `src/worker.ts`, `src/mcp.ts`, `src/http.ts`, `tests/`, `package.json`, `compose.yaml`, and checked-in migrations. Existing reference-project findings and pinned-version compatibility evidence are in [architecture.md](architecture.md). Proposed module/table names in future issues are design decisions to revalidate, not observations of implemented features.

## Execution order and milestone gates

1. Merge the verified M1 foundation. Read the selected issue and its dependencies against the current default branch; do not reimplement work already merged.
2. **M2:** generalize jobs, extract, configure profiles, analyse, group, rank and evaluate. Add developing-digest and read-only intelligence slices as soon as their data owners exist. Acceptance: a client can ask what was found today and retrieve useful explanations with original sources.
3. **M3:** verify/persist/reconcile inbound email, parse originals and attributed links, curate/freeze editions and deliver safely at a configurable time (initially 06:00 Europe/London). Acceptance: RSS plus newsletters feed one briefing and remain independently searchable. This satisfies the handoff's first usable release definition.
4. **M4:** add bounded query-based discovery, GitHub/HN, manual/Reddit paths, explicit-feedback mutations, complete MCP reads, retention/recovery and operational metrics. Acceptance: recorded and permitted live validation shows useful material outside subscriptions; the full-system release gate passes.
5. **M5:** evaluate the nine optional refinements individually. Browser access, embeddings, advanced adaptation/history, alerts/replies, stdio, a UI and new-source recommendations must not become core-release prerequisites.

Milestone labels describe final scope, not a prohibition on useful earlier slices. For example, #9's pure developing-digest logic can be implemented during M2 using fixtures, and #19 can add interest/ranking/draft reads before its final delivery/discovery dependencies are complete. Keep unfinished issue acceptance explicit and close only once its full contracted outcome is accepted.

## MCP surface ownership

`search_items`, `get_item`, `get_sources`, and `get_status` exist in M1. The developing #7 slice adds an initial `explain_ranking` history read. Completing those plus `get_digest`, `get_discoveries`, and `get_interests` belongs to #19, with early additive read slices during M2/M3. The six mutations (`add_source`, `remove_source`, `update_interest`, `submit_feedback`, `ingest_url`, `trigger_discovery`) belong to #18; manual ingestion service/data comes from #17. Optional stdio is #30. No connecting client is required to delegate conversational reasoning back into this service.

## Closure discipline

Required children need merged implementation, linked acceptance evidence and updated operating docs. The core release gate is #23; full handoff coverage and conditional decisions are tracked by #32. A closed issue is not proof by itself: the parent must verify no required work was closed as not planned, replaced with a stub, or left behind in an unmerged PR. Maintain issue links when splitting or superseding work so no requirement loses its owner.

If current provider terms, schema ownership or dependency contracts invalidate an issue, record evidence and replan before introducing a new service or security boundary. A missing live credential blocks live verification, not deterministic implementation and contract tests. M1 is not the complete product; the remaining backlog makes that boundary explicit.
